# FindJob API — описание API

Предметная область: **сервис поиска работы и вакансий**. Компании размещают вакансии,
соискатели откликаются на них и публикуют резюме, также соискатели могут оставлять
отзывы о компаниях.

Стек: Node.js + Express, PostgreSQL, **Prisma ORM 7** (driver-адаптер `@prisma/adapter-pg`).
Авторизация — JWT-токен в заголовке `Authorization: Bearer <token>`.

## Роли системы

| Роль        | Описание                                                        |
|-------------|-----------------------------------------------------------------|
| `guest`     | неавторизованный посетитель (только публичные GET-маршруты)     |
| `applicant` | соискатель (просмотр вакансий, резюме, отклики, отзывы)          |
| `company`   | работодатель (вакансии, отклики на его вакансии, профиль компании) |
| `admin`     | администратор (полное управление пользователями и данными)       |

Базовый URL: `http://localhost:4000`

---

## 1. Аутентификация `/auth`

| Метод | Маршрут         | Описание                       | Доступ        |
|-------|-----------------|--------------------------------|---------------|
| POST  | `/auth/register`| Регистрация (`role`: applicant или company), возвращает JWT | guest (публичный) |
| POST  | `/auth/login`   | Вход по email/паролю, возвращает JWT | guest (публичный) |

> Роль `admin` через регистрацию создать нельзя — только через `POST /user/` (администратор) или seed.

## 2. Пользователи `/user`

| Метод  | Маршрут          | Описание                                   | Доступ                          |
|--------|------------------|--------------------------------------------|---------------------------------|
| POST   | `/user/`         | Добавление пользователя                    | admin                           |
| GET    | `/user/`         | Просмотр списка пользователей              | admin                           |
| GET    | `/user/:id`      | Просмотр конкретного пользователя          | admin                           |
| PUT    | `/user/:id`      | Изменение пользователя (роль меняет только admin) | admin или сам пользователь |
| DELETE | `/user/:id`      | Удаление пользователя (каскадно удаляет связанные данные) | admin      |
| GET    | `/user/profile/` | Просмотр профиля текущего пользователя     | авторизированный (любые роли)   |

## 3. Вакансии `/vacancy`

| Метод  | Маршрут         | Описание                              | Access                     |
|--------|-----------------|---------------------------------------|----------------------------|
| GET    | `/vacancy/`     | Список активных вакансий (поиск/просмотр) | guest (публичный)      |
| GET    | `/vacancy/:id`  | Просмотр конкретной вакансии          | guest (публичный)          |
| POST   | `/vacancy/`     | Размещение вакансии                   | company                    |
| PUT    | `/vacancy/:id`  | Изменение/деактивация вакансии        | company-владелец, admin    |
| DELETE | `/vacancy/:id`  | Удаление вакансии                     | company-владелец, admin    |

## 4. Резюме `/resume`

| Метод  | Маршрут        | Описание                            | Доступ                        |
|--------|----------------|-------------------------------------|-------------------------------|
| GET    | `/resume/`     | Список своих резюме                 | applicant                     |
| GET    | `/resume/:id`  | Просмотр резюме (работодателю — для отклика) | владелец, company, admin |
| POST   | `/resume/`     | Создание резюме                     | applicant                     |
| PUT    | `/resume/:id`  | Изменение резюме                    | только владелец (applicant)   |
| DELETE | `/resume/:id`  | Удаление резюме                     | владелец, admin               |

## 5. Отклики `/response`

| Метод  | Маршрут           | Описание                                         | Доступ                     |
|--------|-------------------|--------------------------------------------------|----------------------------|
| POST   | `/response/`      | Отклик соискателя на вакансию (нельзя повторный) | applicant                  |
| GET    | `/response/my/`   | Мои отклики                                      | applicant                  |
| GET    | `/response/`      | Отклики на вакансии компании                     | company, admin             |
| PUT    | `/response/:id`   | Смена статуса: company — `viewed/interview/rejected/hired`; applicant — только `withdrawn` | company-владелец вакансии, автор-applicant |
| DELETE | `/response/:id`   | Удаление отклика                                 | admin                      |

## 6. Компании `/company`

| Метод  | Маршрут         | Описание                       | Доступ                     |
|--------|-----------------|--------------------------------|----------------------------|
| GET    | `/company/`     | Список компаний                | guest (публичный)          |
| GET    | `/company/:id`  | Карточка компании + её вакансии| guest (публичный)          |
| PUT    | `/company/:id`  | Изменение данных компании      | company-владелец, admin    |
| DELETE | `/company/:id`  | Удаление компании              | admin                      |

## 7. Отзывы о компаниях `/review`

| Метод  | Маршрут                     | Описание                          | Доступ                  |
|--------|-----------------------------|-----------------------------------|-------------------------|
| GET    | `/review/company/:companyId`| Отзывы о компании                 | guest (публичный)       |
| POST   | `/review/`                  | Оставить отзыв (1–5 звёзд, один отзыв на компанию) | applicant |
| DELETE | `/review/:id`               | Удаление отзыва                   | автор-applicant, admin  |

## 8. Служебные

| Метод | Маршрут    | Описание                                       | Доступ |
|-------|------------|------------------------------------------------|--------|
| GET   | `/health`  | Проверка соединения с базой данных (`SELECT 1`)| публичный |

---

## Коды ответов

- `401 Unauthorized` — отсутствует/недействителен JWT;
- `403 Forbidden` — роль/владелец не имеют доступа к действию;
- `404 Not Found` — запись не найдена;
- `409 Conflict` — нарушение уникальности (email, повторный отклик/отзыв);
- `400 Bad Request` — некорректные данные в теле запроса.
