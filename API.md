# FindJob API — описание API

Предметная область: **сервис поиска работы и вакансий**. Компании размещают вакансии,
соискатели откликаются на них и публикуют резюме, также соискатели могут оставлять
отзывы о компаниях.

Стек: Node.js + Express, PostgreSQL, **Prisma ORM 7** (driver-адаптер `@prisma/adapter-pg`).
Авторизация — JWT-токен в заголовке `Authorization: Bearer <token>`.

## Роли системы

| Роль        | Описание                                                        |
|-------------|-----------------------------------------------------------------|
| `guest`     | неавторизованный посетитель (только публичные GET-маршруты)     |
| `applicant` | соискатель (просмотр вакансий, резюме, отклики, отзывы)          |
| `company`   | работодатель (вакансии, отклики на его вакансии, профиль компании) |
| `admin`     | администратор (полное управление пользователями и данными)       |

Базовый URL: `http://localhost:4000`

Фронтенд обращается к API напрямую по базовому URL (в `src/pages/HomePage/HomePage.jsx`
используется константа `API_URL = 'http://localhost:4000'`). В `vite.config.js` также описан
прокси `/api/* → http://localhost:4000` с отбрасыванием префикса `/api`; middleware CORS
в сервере не подключён, поэтому при прямых запросах фронтенд должен идти на порт 4000
(или использовать прокси).

## 1. Аутентификация `/auth`

| Метод | Маршрут         | Описание                       | Доступ        |
|-------|-----------------|--------------------------------|---------------|
| POST  | `/auth/register`| Регистрация (`role`: applicant или company), возвращает JWT (`token`) и созданный профиль (без `passhash`); body: `email`, `password`, `role`, для соискателя — `firstName`, `lastName`, `phone`, для компании — `companyName`; если название компании не указано, берётся email, адрес — «не указан» | guest (публичный) |
| POST  | `/auth/login`   | Вход по email/паролю, возвращает JWT (`token`) и `{ id, email, role }` | guest (публичный) |

> Роль `admin` через регистрацию создать нельзя — только через `POST /user/` (администратор) или seed.

## 2. Пользователи `/user`

| Метод  | Маршрут          | Описание                                   | Доступ                          |
|--------|------------------|--------------------------------------------|---------------------------------|
| POST   | `/user/`         | Добавление пользователя                    | admin                           |
| GET    | `/user/`         | Просмотр списка пользователей (только id, email, role, createdAt) | admin |
| GET    | `/user/:id`      | Просмотр конкретного пользователя (без `passhash`) | admin                  |
| PUT    | `/user/:id`      | Изменение пользователя (роль меняет только admin) | admin или сам пользователь |
| DELETE | `/user/:id`      | Удаление пользователя (каскадно удаляет связанные данные) | admin      |
| GET    | `/user/profile`  | Просмотр профиля текущего пользователя (данные без пароля: company/applicant — целиком, у applicant также его резюме) | авторизованный (любые роли) |

## 3. Вакансии `/vacancy`

| Метод  | Маршрут         | Описание                              | Access                     |
|--------|-----------------|---------------------------------------|----------------------------|
| GET    | `/vacancy/`     | Список активных вакансий (`is_active: true`) по убыванию даты создания; в ответе добавлены поля `salary` (одно число или `null`, если з/п не указана) и `companyId` = id пользователя-работодателя | guest (публичный) |
| GET    | `/vacancy/:id`  | Просмотр конкретной вакансии (включая снятые с публикации, вместе с данными компании) | guest (публичный) |
| POST   | `/vacancy/`     | Размещение вакансии; обязательны `title`, `description`, `location`; принимает как `salary`, так и `salaryFrom`/`salaryTo` | company |
| PUT    | `/vacancy/:id`  | Изменение/деактивация вакансии (`isActive`) | company-владелец, admin |
| DELETE | `/vacancy/:id`  | Удаление вакансии                     | company-владелец, admin    |

## 4. Резюме `/resume`

| Метод  | Маршрут        | Описание                            | Доступ                        |
|--------|----------------|-------------------------------------|-------------------------------|
| GET    | `/resume/`     | Публичный список всех резюме (для карточек на главной); к каждому добавлены `userId` (id автора) и `name` (ФИО соискателя) | guest (публичный) |
| GET    | `/resume/my`   | Список резюме текущего соискателя   | applicant                     |
| GET    | `/resume/:id`  | Просмотр резюме вместе с профилем соискателя и email автора (соискателю — только своё) | владелец, company, admin |
| POST   | `/resume/`     | Создание резюме; обязательны `title`, `skills`, `experience` (принимает и поля `desiredPosition`/`keySkills`/`workExperience`), `isPrimary` по умолчанию `true` | applicant |
| PUT    | `/resume/:id`  | Изменение резюме                    | только владелец (applicant)   |
| DELETE | `/resume/:id`  | Удаление резюме                     | владелец, admin               |

## 5. Отклики `/response`

Все маршруты требуют авторизации (JWT).

| Метод  | Маршрут           | Описание                                         | Доступ                     |
|--------|-------------------|--------------------------------------------------|----------------------------|
| POST   | `/response/`      | Отклик на вакансию; body: `vacancyId`, `resumeId`, необязательная `coverLetter`; нельзя откликаться на снятую с публикации вакансию и чужим резюме; повторный отклик — `409` | applicant |
| GET    | `/response/my`    | Мои отклики вместе с данными вакансии и названием компании, по убыванию даты создания | applicant |
| GET    | `/response/`      | Отклики на вакансии компании (для admin — все отклики); включает название вакансии, ФИО соискателя и заголовок резюме | company, admin |
| PUT    | `/response/:id`   | Смена статуса: company — `viewed/interview/rejected/hired`; applicant — только `withdrawn` | company-владелец вакансии, автор-applicant |
| DELETE | `/response/:id`   | Удаление отклика                                 | admin                      |

## 6. Компании `/company`

| Метод  | Маршрут         | Описание                       | Доступ                     |
|--------|-----------------|--------------------------------|----------------------------|
| GET    | `/company/`     | Список компаний по алфавиту с счётчиками вакансий и отзывов (`_count`) | guest (публичный) |
| GET    | `/company/:id`  | Карточка компании + её активные вакансии | guest (публичный)  |
| PUT    | `/company/:id`  | Изменение данных компании (поля: `name`, `description`, `website`, `address`) | company-владелец, admin |
| DELETE | `/company/:id`  | Удаление компании (каскадно удаляет вакансии и отзывы) | admin              |

## 7. Отзывы о компаниях `/review`

| Метод  | Маршрут                     | Описание                          | Доступ                  |
|--------|-----------------------------|-----------------------------------|-------------------------|
| GET    | `/review/company/:companyId`| Отзывы о компании с ФИО авторов, по убыванию даты | guest (публичный) |
| POST   | `/review/`                  | Оставить отзыв; body: `companyId`, `rating` (целое 1–5), `comment` (обязателен); один отзыв на компанию — иначе `409` | applicant |
| DELETE | `/review/:id`               | Удаление отзыва                   | автор-applicant, admin  |

## 8. Служебные

| Метод | Маршрут    | Описание                                       | Доступ |
|-------|------------|------------------------------------------------|--------|
| GET   | `/health`  | Проверка соединения с базой данных (`SELECT 1`): `{ status, database }` | публичный |

## Коды ответов

Ошибки возвращаются в едином JSON-формате `{ "error": "<текст ошибки>" }`.

- `401 Unauthorized` — отсутствует/недействителен JWT либо неверные email/пароль при входе;
- `403 Forbidden` — роль/владелец не имеют доступа к действию;
- `404 Not Found` — запись не найдена (включая недоступную для отклика вакансию и отсутствующий профиль компании/соискателя);
- `409 Conflict` — нарушение уникальности (email, повторный отклик/отзыв);
- `400 Bad Request` — некорректные данные в теле запроса;
- `500 Internal Server Error` — необработанная ошибка на сервере.

Токен выдаётся при регистрации и входе, срок действия — 8 часов; в payload находятся `id`, `email` и `role` пользователя.

## Переменные окружения (`.env`)

| Переменная     | Назначение                              | Пример |
|----------------|------------------------------------------|--------|
| `DATABASE_URL` | Строка подключения к PostgreSQL          | `postgresql://postgres:postgres@localhost:5432/findjob` |
| `JWT_SECRET`   | Секрет подписи JWT (если не задан — значение по умолчанию из кода) | `dev-secret-change-me` |
| `API_PORT`     | Необязательный порт REST-сервера (по умолчанию `4000`) | `4000` |

## Запуск backend

```bash
npm run db:migrate   # применение миграций Prisma
npm run db:seed      # заполнение базы тестовыми данными
npm run server       # запуск REST API на http://localhost:4000
```
